## 1. 游戏环境

### 1.1 官方规则里已经能用的部分

2026-10-15 抓取的页面：[TexasHoldem2p - Botzone Wiki](https://wiki.botzone.org.cn/index.php?title=%E7%89%B9%E6%AE%8A:%E6%88%91%E7%9A%84%E8%AF%AD%E8%A8%80/TexasHoldem2p)。下面这些句子在该页上是一致的：

- 两人，每小局开始双方筹码都回到 20000。小盲 50，大盲 100。一场默认 50 小局。
- 庄家每小局交给下家。二人时：庄家的下家下小盲，庄家自己下大盲（`dealer` 的下下家就是庄家）。翻牌前从小盲开始；翻牌、转牌、河牌也从庄家的下家（小盲）开始。
- 响应是一个整数：`-1` 弃牌，`-2` 全押，`0` 跟注或过牌，正整数是**这一下额外投入的筹码**（不是 raise-to）。
- 有人全押之后，这一小局只允许弃牌或全押。全押后不再收到请求，直接摊牌或结束。
- 跟注要求剩余筹码**严格大于**需要跟注的数量；加注的正整数必须**严格小于**剩余筹码。不够就只能弃牌或全押。非法响应、崩溃、超时，裁判都当成弃牌。
- 每步 1 秒。交互是 JSON：读入 `requests` 的最后一条（整手状态，不是增量），输出 `{"response": <int>}`。
- 分数是整场累计赢得筹码除以 100。牌号 0–51：`点数 = n // 4 + 2`，`花色 = n % 4`，顺序是红桃、方块、黑桃、草花。
- 简单版和 [TexasHoldem2p-complex](https://www.botzone.org.cn/game/TexasHoldem2p-complex) 不是同一个游戏。complex 才跨小局继承筹码，并使用标准边池。本方案只做简单版。

二人、每手重置 20000 时，双方总筹码恒为 40000。一人全押后另一人要么弃牌要么也全押，两人全押则各投入 20000。简单版**不会出现边池**。环境每一步都要断言 `双方剩余 + 底池 = 40000`。

### 1.2 和现有牌桌的差别

`PokerkitTable`（`tables.py`）是标准单挑：座位 1 是按钮兼小盲，翻牌后**大盲先动**，最小加注是 PokerKit 的「补足上一次完整加注」。`RlcardTable` 翻牌后仍是小盲先动，和 Botzone 的行动顺序相同，但盲注是 1/2、起始 100、没有 Botzone 这套加注整数，也不把「有人全押」收成只能弃牌或全押。

所以 Botzone 不能靠把 `starting_stack` 改成 400、`big_blind` 改成 100 来假装。那样只是 200bb 的 PokerKit，行动顺序和加注合法性都还是错的。

新牌桌单独做，建议放在 `src/alphanl/botzone/table.py`，用 `env.backend = "botzone"` 接进现有的 `make_table` / `SelfPlayEnv`。rlcard 和 pokerkit 的行为、测试、checkpoint 保持不动。checkpoint 里已经有 `backend` 和盲注；载入到另一个后端现在就会报错，这个约定继续用。

二人时的行动顺序和 rlcard 一样都是「每条街小盲先动」，但只共享这个事实。不要把 Botzone 的下注记进 rlcard 的 5 档重放（`history.replay_events`），那边的筹码公式是 `int(底池/2)`。

### 1.3 加注额：wiki 自己不一致

正整数的含义（额外筹码）是清楚的。**最小要多少**，同一页有三种说法：

| 出处 | 说法 |
|------|------|
| 非法操作第 4 条 | 少于「本轮最大下注筹码的 2 倍」则非法；本轮第一个加注者少于大盲也非法 |
| 人类操作说明 | 不少于「本轮最大加注的 2 倍」 |
| 页末 Python 样例 | 可执行。翻前 `round_raise = 200`；每次加注 `extra` 之后 `round_raise = max(round_raise, 2 * extra)`；新的一条街重置为 100 |

样例在「翻前第一次加注至少 200」和「翻牌后第一次下注至少 100」上，和非法条款对得上。一旦已经有过加注，两者就分开。例：小盲额外投入 200，本街累计变成 250。样例允许下一次额外投入 400（`2 * 200`）。若「最大下注」指本街累计 250，非法条款要求至少 500。400 在样例里合法，在这种读法里会被裁判改成弃牌。

仓库里没有裁判源码，也没有一条真实对局可以判定哪种读法对。本次也不把样例程序当成裁判。

**倾向：发出去的加注同时满足两种下界，取更严的那个。** 这样无论裁判采用哪一种，这一注都不会因为「太小」被改成弃牌。代价是最小加注偏大，小额试探这一版学不到。等有一条 Botzone 导出的对局，再把下界收成裁判真正接受的那个数；那是单独一步，不跟训练缠在一起。

记两个下界，动作发出前取 max：

- 下界 A（按累计下注）：本街还没有自愿下注时为 100；否则为 `2 * 本街最大累计投入`（翻前盲注算累计，所以翻前开局是 `2 * 100 = 200`）。
- 下界 B（按样例）：翻前从 200 起；每次真实发生的加注把下界改成 `max(下界, 2 * extra)`；新街重置为 100。
- 安全额外筹码 `safe = max(A, B)`。还要求 `safe < 我的剩余筹码`，且本手还没有人全押。否则这一档加注不存在。

跟注 / 过牌发出 `0` 的条件：本手无人全押，且剩余筹码严格大于待跟筹码（待跟为 0 就是过牌）。全押发出 `-2`，只要剩余筹码大于 0 就提供。弃牌发出 `-1`，样例在每个决策都提供，包括可以免费过牌的时候。wiki 没有写「能过牌时禁止弃牌」。现有 PokerKit 路径会用 `can_fold()` 拿掉免费弃牌（`docs/step3_transformer.md`）。Botzone 牌桌与样例对齐，**保留免费弃牌**。策略会不会滥用它，用第 6 节的熵和弃牌率看，不在规则层先藏起来。

### 1.4 验收用的五手棋

实现必须把这五手做成测试。数字按上面的安全下界手算，dealer = 0（座位 0 下大盲，座位 1 下小盲）：

1. 翻前小盲第一个说话。待跟 50。弃牌、跟注 `0`、全押 `-2` 都合法。安全加注是 200。发出 200 后，小盲本街累计 250，底池 350，下界 B 变成 400。
2. 接着大盲说话。待跟 150。跟注合法。下界 A = 500，下界 B = 400，所以最小加注发出 **500** 而不是 400。
3. 翻前双方跟注到摊牌前，翻牌圈无人下注。最小下注是 100，不是 200。
4. 任意一人已经全押。另一人只有 `-1` 和 `-2`。`0` 和任何正整数都非法。
5. 待跟筹码恰好等于剩余筹码。`0` 非法（必须严格大于），全押合法。

另外用随机种子打 1000 手：每一步 `剩余 + 底池 = 40000`；双方盈亏之和为 0；牌桌自己生成的响应再喂回合法性函数，结果必须是合法。奇数底池平分时，**多出来的 1 筹码先给座位号较小的一方**。wiki 没写余数归谁【未核实】，写死是为了测试可重复，有真实回放再改这一行。

烧牌：wiki 只说翻出公共牌，没写烧牌【未核实】。随机洗牌时烧不烧不影响牌的分布。牌桌内部按常规烧牌发牌即可。和裁判对拍时用请求里的 `public_cards`，不要用我们自己的牌序去猜裁判。

摊牌牌型用 wiki 列出的九种高牌。`requirements-transformer.txt` 钉了 `pokerkit==0.7.7`，但本环境没装这个包，所以这里不写具体函数名。实现时用 0.7.7 的高牌接口包一层；包不住就在本地写比牌，并用同花顺、四条、葫芦、A-5 顺子、公牌平分这几条测试锁住。A-5 是否为最小顺子，wiki 没点名【未核实】，测试按常规德州先写成是，回放不一致再改。

### 1.5 和裁判对齐的办法

分三层，不要跳：

1. **纯函数。** `legal_response(state) -> {-1,-2,0} ∪ 正整数` 与 `apply(state, response)` 不依赖 PyTorch。第 1.4 节的五手棋先绿。
2. **自洽。** 随机对局 1000 手，发出的每个响应都能被同一个函数接受；非法响应在测试里被标成弃牌，确认状态机和「非法即弃牌」一致。
3. **真实对局。** 从 Botzone 导出至少一条完整对局 JSON（含每步 request 和裁判记录的 response）。用我们的函数重放：公共牌、剩余筹码、胜负、累计分数和裁判一致。这一层过了，才把环境标成「已对拍」。过不了就只改下界函数，不动网络。

没有第 3 层也可以做短程 PPO：安全下界保证我们发出的加注在两种读法下都不是「太小」。长训可以开始，但指标和文档里写明「裁判未对拍」。不把样例机器人的随机策略当成裁判。

训练按**单手**采样，因为筹码每手重置，单手筹码期望就是评分的期望。庄家每手随机（现有英雄随机换边保留）。50 手、庄家交替只放在评测里，用来报 Botzone 那种「累计筹码 / 100」。

## 2. 动作空间

策略头继续输出 5 个概率。`schema.py` 里的名字从 `raise_half_pot` / `raise_pot` 改成下面两档，**宽度不变**。半池那一档在安全下界下经常小于 `safe`，留着只会和最小加注变成同一个响应。

| id | 名字 | 发出的响应 | 什么时候从掩码里拿掉 |
|----|------|------------|----------------------|
| 0 | `fold` | `-1` | 不拿掉 |
| 1 | `check_call` | `0` | 有人全押，或剩余筹码 ≤ 待跟 |
| 2 | `raise_min` | `safe` | `safe` 不存在（见第 1.3 节） |
| 3 | `raise_large` | `max(safe * 2, 底池)` | 该数 ≥ 剩余筹码 |
| 4 | `all_in` | `-2` | 剩余筹码 ≤ 0 |

底池用行动前的总底池，和现在 `PokerkitTable._chips_if_legal` 里「一倍池 = 本次投入等于底池」同一口径。`safe > 0` 时 `safe * 2` 一定大于 `safe`，所以这一档不会和最小加注变成同一次响应，不需要再为「重复」写一条屏蔽。第 1.4 节第 2 手里，大盲的 `safe = 500`、底池 350，因此 `raise_large = 1000`。全押即使和某一档只差几块钱也单独保留，因为线上协议里全押是 `-2`，不是一个大正整数。

掩码和发包走**同一个函数**：某个 id 留在掩码里，当且仅当它对应的整数通过 `legal_response`。环境、对手、以后的 Botzone 进程都不准另写一套「差不多合法」的换算。现有 `masked_log_probs` 在 softmax 之前把非法 logit 写成 `-1e9`，这一处不用改。

`c_1048` 的 5 个数是另一套筹码（50bb、`int(底池/2)`、没有这条最小加注）。同一个整数 id 在两边意思不同。`backend=botzone` 时，`scripts/train_transformer.py --init-weights` 默认拒绝；只有显式打开一个开关才允许载入。避免把 rlcard 上的行为克隆权重静默灌进新头。

## 3. 观测编码

序列形状保持 `docs/step3_transformer.md` 里的那条，CLS 仍在下标 0，策略和价值都读它：

```
[CLS] [HOLE] [洞牌] [洞牌]
[STREET_preflop] [动作] ...
[STREET_flop] [三张公共牌] [动作] ...
[STREET_turn] [转牌] [动作] ...
[STREET_river] [河牌] [动作] ...
```

每个动作 token 继续打包四件事：语义（fold / check / call / bet / raise / all-in）、SB 或 BB、是不是「我」、底池比例桶。桶的边界不动（`buckets.py`：0、0.25、0.5、0.75、1、1.5、2、4、更大）。盲注不单独做 token。Botzone 的 `history` 里也没有盲注，双方都从 `dealer_id` 推。第一下决策的 CLS 数值必须已经含盲注：底池 150，小盲剩余 19950，大盲剩余 19900。

现有数值是 4 维，筹码除以 `starting_stack`（`tokenizer._norm_chips`）。CLS 上是底池、我的筹码、对手筹码、待跟；动作上是截断到 10 的底池比例再除以 10，以及行动前的底池、筹码、待跟。起始 20000 时，一个大盲是 `100/20000 = 0.005`，和底池比例那种 0.1 量级挤在一起。

改成下面这一条，词表和 token id 不动，只改数值：

```
norm(筹码) = log1p(筹码 / 大盲) / log1p(200)
```

大盲 100、深度 200bb 时：1 个大盲约为 0.131，200 个大盲为 1。底池比例那一维保持原来的截断。这样 50bb 和 200bb 以后若共用意数值通道，深度进分母，不会把起始筹码的绝对大小写进权重。本仓库还没有值得保留的 Transformer 训练权重（正式训练没跑过），这次改数值不会浪费 checkpoint。

超长仍丢最旧的动作，留下 CLS、洞牌和还有动作的街标记。按安全下界，加注大约每步翻倍，一手牌在全押前的动作次数是对数级：粗算每街最多大约 8 次加注，四条街加上牌和街标记，落在 64 以内。这是按本方案的下界数的，不是实测牌谱。笔记本配置的 `max_seq_len = 64` 够用，不必为了 200bb 改成 Colab 那份的 96。

比赛进度（第几手、累计赢的筹码）v1 不放进观测。奖励是单手筹码，放进去模型会看到一个奖励里没有的信号。样例只用它做最后一手的特判，那不是本方案的目标。

牌号在进 tokenizer 之前换成现有的花色+点数（`SA` 这种）。转换表按 wiki：0 红桃 2，1 方块 2，2 黑桃 2，3 草花 2，以此类推。transformer 词表里不出现 0–51。

## 4. Transformer 结构

用现有 `PokerTransformer`，不换结构：

- token、类型、位置三种嵌入，加上数值的线性投影，Pre-LN 的 `TransformerEncoder`，`enable_nested_tensor=False`。
- CLS 过一层 GELU，再分成策略头和价值头。
- 策略头：5 维 logits，非法动作掩掉之后做 softmax，得到概率分布。头用 gain 0.01 的正交初始化，开局在合法动作上接近均匀。
- 价值头：一个标量。预测的是第 6 节里缩放后的回报，不是原始筹码。
- 策略头、价值头、掩码、softmax 保持 fp32。这是现有 AMP 的做法，`-1e9` 在 fp16 里会变成 NaN。

规模用笔记本这份，训练和以后提交 Botzone 用**同一个**宽度：

| | 采用 | 不采用作 v1 提交 |
|--|------|------------------|
| 配置 | `laptop_8gb.json` 的 `model` 段 | `colab_l4.json` 的大网络 |
| 宽度 | 128 / 4 层 / 4 头 / FFN 256 / 序列 64 | 256 / 6 / 8 / 1024 / 序列 96 |
| 参数量 | 文档记载 592,390 | 文档记载 4,904,454 |

显存：PR #7 在 RTX 3070 Laptop 上用这份小网络、AMP、10 个 update，峰值 `max_memory_allocated` 0.331 GB。8GB 够。`docs/step3_transformer.md` 里对大网络「大约 2GB」的估计写明了**没有量过**，本方案不把大网络当 v1。

Botzone 侧的限制要分开看：

- 每步 1 秒：wiki 写了。0.6M 参数、序列几十，CPU 前向远小于 1 秒。仍要在提交形态上计时，不靠这个判断代替测量。
- 内存 256MB：本次 wiki 页面**没有**写 256MB，这是任务给定的上限【页面未记载】。权重本身 fp32 大约 2.4MB。风险在运行时而不在参数量。Botzone 的 Python 镜像有没有 `torch`，本次没有查到【未核实】。`import torch` 的常驻内存往往已经吃掉这个上限。
- 正式比赛不能写用户存储。权重打进提交物。

**倾向：训练继续用 PyTorch；提交用一份不 import torch 的 NumPy 前向，和 `PokerTransformer.forward` 对同一批输入，logits 最大绝对误差 < 1e-4。** 在本机把这个进程的 RSS 打出来。256MB 和镜像的真实限制等提交前再对一次文档；对不上就缩小依赖，不放大网络。

Colab L4/T4 若要加速，只加大 `num_envs` 和 rollout，**不加宽** v1 网络。现有 `colab_l4.json` 是大网络，不要直接拿来训这份要上 Botzone 的策略。

## 5. 训练流程

### 5.1 先不要做行为克隆

现成的教师是 `c_1048`：卷积网、5 档、50bb、rlcard 没有这条最小加注、价值是 IMPALA 的筹码尺度。导出脚本在 Python 3.7 里打 rlcard（`scripts/dump_c1048_bc.py`），`train_bc.py` 用 KL 去拟合。这些数据里的动作 id 和本方案的响应不是一回事。拿来热启动会把「半池」教成「安全最小加注」。

Slumbot 是标准最小加注、翻牌后大盲先动，客户端还把我方截在 50bb。不能当 Botzone 教师，也不能当 v1 的过关对手。

**倾向：v1 从现有的小初始化直接 PPO。** 合法动作上的初始策略已经接近均匀，熵系数留 `0.01`。只有第 6 节判定「塌成弃牌」之后，才加一步行为克隆，教师是**本仓库的 Botzone 规则 bot** 在新牌桌上打出来的牌谱，走现有 `train_bc.py` 的 KL。不为此去跑 TF 1.15。

`c_1048` 仍保留为 50bb rlcard 上的历史对照，用现有 `eval/eval_step1.py`。不写一个「把 Botzone 状态硬填进卷积观测」的适配器，那个数字没有意义。

### 5.2 PPO 自我对弈

循环用现有的：CPU rollout，GPU 上做 PPO，AMP，原子 checkpoint，`--resume`。损失不变（clip、价值 clip、掩码后的熵）。`gamma = 1`。Advantage 仍按整个 rollout 标准化。

对手池保持现在的 PFSP（`pool.py`）：每手以 `random_prob` 抽均匀随机，`selfplay_prob` 抽当前网络，其余按 `(1 - 胜率)^2` 抽冻结快照，胜率封顶 0.95。快照是赢 1 / 平 0.5 / 输 0，不是 bb。这不是上游的 K-best，也不另训 exploiter。v1 不改采样公式。`cache_opponents` 保持默认开启。

奖励改在 Botzone 后端上，别的后端先不动，避免旧测试的 bb 尺度漂移：

```
进入 GAE 的奖励 = (英雄筹码变化) / 大盲 / 200
```

价值头拟合大约 `[-1, 1]` 的「起始深度的几分之一」。日志里的 bb/手 = 这个数 × 200。现在的 `_hero_bb` 只除了大盲，50bb 时回报大约 ±50；200bb 时大约 ±200，价值损失会比策略损失更占梯度（`docs/step3_transformer.md` 已写过 ±50 的情况）。PFSP 只看奖励的符号，除以 200 不改变抽对手的权重。

`SelfPlayEnv._play_until_hero` 现在限制对手连续行动不超过 64 次。在「加注至少翻倍」下到不了这个上限。若以后把下界改松、允许很多小注，先改这个上限再训练。

### 5.3 对手和评测

| 对手 | v1 里的角色 | 怎么打 |
|------|-------------|--------|
| 均匀随机合法动作 | 必测 | 新牌桌的 `legal_action_ids` |
| 规则 bot | 必测，过关线之一 | 新写，下一段。不复用 `RuleBot` 对 rlcard 的 `make_action` |
| `c_1048` | 历史对照 | 只跑现有 50bb rlcard 评测 |
| Slumbot | 不作为 v1 过关线 | 规则不同。以后若另训一版标准 200bb，再用现有客户端，并分开报告截断和未截断 |
| 池里的旧快照 | 训练对手 | 现有 PFSP |

规则 bot 按 `src/alphanl/bots.py` 里 `RuleBot` 的强度分档，但动作改成新的 5 档。翻前用那份点数表（对子、高张、同花连张）。翻牌后先比牌型；比牌函数还没落地时，用它已有的对子/两对/三条计数。在**当前合法集合**里按优先级选：

| 强度 | 优先级 |
|------|--------|
| 高（原代码 ≥ 7，或翻前对子 A/K） | 全押，其次 `raise_large`，其次 `raise_min`，其次跟注，最后弃牌 |
| 中（≥ 4） | `raise_min`，其次 `raise_large`，其次跟注，其次全押，最后弃牌 |
| 低（≥ 2） | 跟注，其次 `raise_min`，其次弃牌，其次大注和全押 |
| 其余 | 能过牌就过牌；面对下注则弃牌，其次跟注 |

这只是一个稳定的弱对手，用来当尺子。不调参去模仿 Botzone 排行榜。

指标沿用 Step 1 的正态区间：均值 ± 1.96 × 样本标准差 / √n。同时报两列：

- **bb/100** = 平均每手大盲 × 100。过关看这个。
- **一场分** = 50 手、庄家交替，累计筹码 / 100。至少 100 场（5000 手）报一场分的均值，让数字和 Botzone 排名的单位一样。一场只有 50 手，方差大，过关不看一场分的胜负。

50bb rlcard 上的 mbb/hand 和这里的 bb/100 是两种游戏，表格里分开写，不相减。

### 5.4 每一段的验收

1. **规则函数。** 第 1.4 节五手棋全部通过；1000 手随机对局筹码守恒、盈亏相加为 0、没有发出非法响应。
2. **接到训练循环。** `backend=botzone` 跑通现有那种「2 步 rollout + 1 次 PPO」的接线测试；checkpoint 来回载入后盲注仍是 50/100、起始仍是 20000；rlcard checkpoint 载入这个后端要失败。
3. **没塌。** 笔记本上 200 个 update（AMP 开）。没有 NaN/Inf，峰值显存 < 7GB。这 200 步里，合法动作上的平均熵低于 0.2 且「可以过牌时仍弃牌」的比例高于 0.5，就判定塌缩，停，去做规则 bot 的行为克隆，然后再 PPO。不把塌掉的权重接着训。
4. **强于两只弱对手。** 用同一套评测先量「规则 bot 对随机」的 bb/100，记为 R。再量 Transformer（采样，不是贪心；Botzone 要的是混合策略）对随机、对规则 bot，各 5000 手，座位和庄家都换过。过关条件：对规则 bot 的 95% 区间下界 > 0，并且对随机的点估计 ≥ R。区间若含 0，把手数加到 20000 再算一次；仍然含 0 就不过关。在 R 量出来之前不写死一个 bb 阈值。Step 1 那种 1600 mbb/hand 是 50bb rlcard 上对很弱对手的结果，不能拿来当这里的目标。

第 4 步之前用 `--profile-rollout` 记一次新牌桌的每步耗时。只记录，不在这一步改速度。

## 6. 里程碑

一次只改一件事。前一件的验收没过，不开始后一件。

交给**简单代码 bot** 的条件：行为已在本文写死，改动落在一两个文件，验收就是新测试变绿。交给**复杂云端 agent** 的条件：要碰规则分歧，或者要跨牌桌、训练循环和 checkpoint。

| 步 | 只做这一件事 | 谁来做 | 怎样算做完 |
|----|----------------|--------|------------|
| M1 | 合法性纯函数和下界 A/B，含五手棋。不发牌、不训练 | 复杂 agent | 第 1.4 节测试绿 |
| M2 | `BotzoneTable`：发牌、按钮、盲注、摊牌、筹码守恒。还不进 PPO | 复杂 agent 写牌桌；五手棋之外的随机对局测试交给简单 bot | 1000 手守恒测试绿 |
| M3 | 5 档动作只通过 M1 的函数变成响应，掩码与响应一致 | 复杂 agent | 每个未屏蔽 id 的响应都合法；被屏蔽的 id 没有响应 |
| M4 | `env.backend=botzone` 接上 `SelfPlayEnv`。checkpoint 带新后端。`botzone` 下默认拒绝 `--init-weights` | 复杂 agent | 接线测试、旧 checkpoint 互载失败 |
| M5 | 数值特征改成 `log1p` 公式。词表不动 | 简单 bot | 原有 token id 测试仍绿；数值有单独的期望值 |
| M6 | 仅 botzone 后端的奖励改为除以大盲再除以 200；日志乘回 bb | 简单 bot | 已知底池的一手，奖励和日志 bb 与手算一致 |
| M7 | 规则 bot + 评测脚本（bb/100、区间、50 手一场） | 简单 bot。优先级表以本文为准，不要自己发明强度 | 规则 bot 对随机能打出一份带区间的 bb/100 |
| M8 | 一份新 json：backend、盲注 50/100、起始 20000，网络宽度与 `laptop_8gb.json` 的 `model` 相同 | 简单 bot | `--dry-run` 参数量仍是 592,390 这一档 |
| M9 | 笔记本跑 200 个 update | 人。agent 不改算法 | 第 5.4 节第 3 条。塌了才做 M10 |
| M10 | 只在塌缩时：规则 bot 的牌谱 + 现有 `train_bc.py` | 复杂 agent | KL 下降，且载入后熵回到 0.2 以上 |
| M11 | 正式 PPO | 人在笔记本或 Colab 上跑小网络 | 第 5.4 节第 4 条 |
| M12 | NumPy 前向，对拍 logits，量 RSS 和单步耗时 | 复杂 agent | 误差 < 1e-4；本机 RSS 和耗时写进文档。不在这一步注册 Botzone 账号或提交排名 |

M2 可以在没有真实对局的情况下做完。有对局之后，若下界要改，只重开 M1，再跑一遍 M3 的测试；网络宽度不动。

速度如果不够，单独开一步「多进程 rollout」。不要和 M4 绑在一起。现有剖析入口是 `scripts/smoke_metrics.py --profile-rollout`。

## 7. 哪些能搬到日麻

日麻是四人（或三人）、得分是点数和顺位，没有底池，也没有「额外筹码」这种动作。能搬走的是训练骨架，不是德扑状态。

可以直接搬：

- `PokerTransformer` 里 CLS 之前的那一段：嵌入、数值投影、Pre-LN 编码器、PAD 掩码、从 CLS 分出两个头。头的宽度已经是构造参数。
- `ppo.py` 的 GAE、clip、价值 clip、掩码后的熵。动作数不要写死成德扑的 5，日麻接进来时只改头宽和掩码。
- `train.py` 的「CPU 采样、GPU 更新、AMP 时头保持 fp32、原子 checkpoint、`--resume`」。
- `pool.py` 的「随机 / 当前网络 / 按胜率抽快照」这种池子结构，以及 `cache_opponents` 这种按快照 id 缓存冻结网络的做法。
- `smoke_metrics.py` 的分步计时。
- tokenizer 的框架：类型嵌入、右侧 PAD、超长时丢最旧的事件、CLS 上挂连续特征。

必须按游戏重写：

- 规则、合法性、和 Botzone 日麻协议的整数或字符串响应。德扑这份 `legal_response` 不能用。
- 动作档位。日麻的弃牌、吃碰杠、立直不是 5 个下注档。
- 词表里具体的牌、鸣牌、宝牌、立直、舍张。底池比例桶没有对应物。
- 奖励。点数和顺位替换「筹码 / 大盲 / 200」。
- 环境循环。现在是两人、英雄一步、对手连着打到该英雄。四人要四家轮流行动，对手池里「一个对手策略打另一个座位」不够。
- 评测对手。`c_1048`、Slumbot、本文的规则 bot 都是德扑的。

行为克隆脚本的「对教师概率做 KL、非法动作从两边分布里去掉」可以留，教师数据格式要换。

## 8. 风险和倾向

| 风险 | 事实 | 倾向 |
|------|------|------|
| 最小加注有两种读法 | wiki 非法条款和样例在加注发生之后不一致。没有裁判源码，也没有 T-D2 | 发出的注取更严的下界。用真实对局再收紧。收紧之前允许长训，但标明未对拍 |
| 翻牌后谁先动 | Botzone 与 rlcard：小盲先动。PokerKit：大盲先动 | 新 backend。不改 PokerKit，留给以后真正的标准规则 |
| 有人全押后不能跟注 | wiki 非法条款第 5 条；简单版两人重置筹码，所以不会有边池 | 掩码只留弃牌和全押。不用 PokerKit 的跟注 |
| 免费弃牌 | 样例始终提供弃牌；现有 PokerKit 路径会拿掉 | Botzone 牌桌保留。用弃牌率判断要不要管，不在 v1 改掩码 |
| `c_1048` 当教师或对手 | 50bb、另一套 5 档、另一套行动顺序的价值尺度 | 只保留 Step 1 的历史数字。Botzone 训练默认不载入那份权重 |
| Slumbot | 标准规则 + 客户端 50bb 截断 | 不做 v1 过关线 |
| 价值尺度 | 现有回报是大盲。200bb 时大约 ±200 | 只在 botzone 后端再除以 200 |
| 策略塌成弃牌 | 调研笔记里写过同类现象。熵系数 0.01 还没扫过 | 200 update 的熵和弃牌率作为闸门。塌了再用规则 bot 做 KL，不先做 `c_1048` 克隆 |
| 256MB 里跑 PyTorch | 1 秒是 wiki 写的。256MB 是任务给定，这次抓取的 wiki 页没写。镜像里有没有 torch【未核实】 | 提交用 NumPy 小网络。先量 RSS，再谈提交 |
| 速度数字对不上 | 仓库：PR #7 为 CPU rollout 约 6.2 s/步、GPU 更新约 0.45 s/步、峰值 0.331 GB（10 步，小网络，AMP）。PR #8 为缓存后笔记本 CPU rollout 从 7.41 s 到 5.26 s，对手加载降到 0。`docs/training.md` 估计每步 7–9 秒。这些都不是 1.2 s，也不是 8 个进程 | 以 `--profile-rollout` 在新牌桌上重新量。多进程单独开里程碑。用户那组 1.2 s 在有同样的命令和日志之前，不当作已实现的基线 |
| 奇数底池的 1 点筹码、A-5 顺子、烧牌 | wiki 没写死 | 测试里写死当前约定，对拍失败只改那一行 |
| AGPL | AlphaNLHoldem 是 AGPL，仓库因此保持私有 | Botzone 牌桌自己写，不把上游裁判或 TF 图打进提交物 |

未解决、但不阻塞 M1–M8 的只有一件事：还没有一条裁判回放，因此下界 A 和 B 谁才是真规则还不知道。阻塞长训结论的是第 5.4 节的过关线，不是缺一个更大的网络。
